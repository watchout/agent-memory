# 要件 — 席の記憶を自社か顧客の DB に保ち、どの席も続きから再開できる

- 依頼の原文: 「施設向け管理AXシステムの記憶を、自社か顧客のDBの中で保ち、どのエージェントも続きから仕事を再開できる」
- 深さ: Standard（範囲は複数の部品にまたがり、別の役割の席への引き継ぎ・顧客の層など今の版に無い所がある）
- 種類: 既存の仕組み（Kusabi 0.3.0）への機能追加

## 意図の分析

- 目的は、席（自社の席として動く AI。Claude・Codex・Gemini など種類を問わない）が、担当の交代・再起動・文脈の圧縮の後でも、人が経緯を説明し直さずに続きから仕事を始められること。（意図の文書の問題と成功の測り方）
- あわせて、記憶がどこにあり誰が見られるかを顧客ごとに示せること。記憶は自社か顧客の DB の中で完結させる。（意図の文書の成功の測り方、制約 C-13）
- 今の版は「同じ役割の席が、種類を替えても自分の記憶を読める」所までを持つ。足りないのは、別の役割の席への引き継ぎ、顧客ごとの置き場所と隔離、外への送り出しを止めること、読み書きできる者の一覧、今の記録の移し。（今のコードの読み解き `aidlc/spaces/default/codekb/agent-memory/architecture.md` の改善の余地）
- まず得をするのは自社の席と、席に仕事を任せる owner・開発運用。最初の利用者は社内の開発の席で、置き場所は自社の DB から始める。（意図の文書、制約 C-19）

## 機能の要件

### FR1 席の見分け（P1）

- **FR1.1** Kusabi は、書き手と読み手の席を、共通基盤のエージェントの管理の登録から決める。自前の席の一覧を持たない。（範囲 P1、制約 C-03）
  - 合格: 登録済みの席が書いた記録に、その席の共通基盤の識別子が付いている。
- **FR1.2** 共通基盤に登録の無い席からの読み書きは受け付けず、「この席は共通基盤に登録されていない」と理由を返す。（範囲 P1、角の一覧「記録の持ち主が無い」）
  - 合格: 登録の無い席として道具を呼ぶと、記録は増えず、理由つきの失敗が返る。
- **FR1.3** 席の種類（Claude Code・Codex・Gemini）が替わっても、共通基盤で同じ席なら同じ記憶を読み書きする。（範囲 P2、場面 S3）
  - 合格: 同じ席として Codex の席が書いた決定を、Claude Code の席が読める。
- **FR1.4** 席の所属の顧客は、共通基盤の所属から決まる。1 つの席は一度に 1 つの顧客の仕事だけをする。（Q3 = A）
  - 合格: 所属が顧客 X の席の記録は、すべて顧客 X のものとして保たれる。

### FR2 別の役割の席への引き継ぎ（P2）

- **FR2.1** 席は、決定・作業の状態・学びを書く時に、仕事の ID（その仕事の GitHub の issue か PR の URL）を付けられる。（Q2 = A）
- **FR2.2** 仕事の ID は 1 つの正規の形（`owner/repo#番号`）にそろえて保つ。URL の書き方の違い（http と https、末尾の `/`、`#issuecomment-…` の付き、`/issues/` と `/pull/` の違い）で別の仕事にしない。（角の一覧「1 つの物に複数の名前」）
  - 合格: 同じ issue を指す 4 通りの書き方で付けた記録が、1 つの仕事の ID で全部読める。
- **FR2.3** 同じ顧客の席は、仕事の ID を指定して、その ID が付いた記録を、どの席が書いた物でも読める。返す記録には、書いた席・時刻・仕事の ID が付く。（Q2 = A）
  - 合格: 席 A が仕事 W の決定を書き、席 B が W を指定して読むと、席 A の名前つきでその決定が返る。
- **FR2.4** 仕事の ID が付いていない記録は、今までどおり書いた席だけが読める。（Q2 = A の要約の確認、今の記憶の境目）
  - 合格: 仕事の ID の無い席 A の記録は、席 B からは読めない。
- **FR2.5** 別の顧客の席は、同じ仕事の ID を指定しても読めない。（Q3 = A、NFR2）
  - 合格: 顧客 Y の席が仕事 W を指定しても、顧客 X の記録は 1 件も返らない。
- **FR2.6** 仕事の ID に記録が無い時は「この仕事の記録は無い」と返し、失敗とは分ける。（角の一覧「空」）
- **FR2.7** 同じ仕事に複数の席が作業の状態を書いた時、席ごとに別々に残し、上書きで消さない。仕事の ID で読むと、全部を時刻の順に返す。（角の一覧「同時の書き込み」）

### FR3 担当交代と再起動の後の取り出し（P3）

- **FR3.1** 席の起動の時と圧縮の後に、その席の進行中の作業・有効な決定・学びを、回復の内容として席に渡す。今の起動の口（Claude Code・Codex・Gemini）を新しい置き場所でも動かす。（範囲 P3、場面 S1・S2）
  - 合格: 席を開き直すと、最初の文脈に前の会話の進行中の作業と有効な決定が入っている。
- **FR3.2** 仕事の ID を 1 つ渡すと、その仕事の決定・作業の状態・学びを、1 回の呼出しでまとめて返す道具を持つ。（Q7 = B）
  - 合格: 道具を 1 回呼ぶだけで、その仕事の 3 種類の記録が返る。
- **FR3.3** 回復の内容と FR3.2 の応答は、記録を「データ」として出す（書いた席・時刻・仕事の ID つき）。記録の中に命令の形の文があっても、席への指示として扱わない。（角の一覧「信頼できない中身が AI を動かす」）
- **FR3.4** 回復の内容や応答に入りきらない時は、省いた件数と、続きを取り出す方法を書く。黙って切らない。（角の一覧「文脈の上限」）

### FR4 取り出せる割合の試験（P4）

- **FR4.1** 次の 5 つの場面の試験を持つ。各場面は合成のデータで記録を作り、前の担当の決定・作業の状態・学びが取り出せるかを確かめる。（Q1 = A、決定 D-24）
  - S1 同じ席の再起動
  - S2 文脈の圧縮の後
  - S3 同じ役割の席の種類の交代
  - S4 別の役割の席への担当交代
  - S5 Gemini（使い捨ての会話）を含む交代
- **FR4.2** 「取り出せた」と数えるのは、起動の時の回復の内容に入っている時か、指示に書かれた仕事の ID だけを使って道具を 1 回呼んで取り出せた時。（Q7 = B）
- **FR4.3** 取り出せる割合 = 取り出せた記録の数 ÷ 試験の場面で作った記録の数。母数に今の記録を入れない。（決定 D-26）
- **FR4.4** 対応表で席に結べなかった古い記録の件数は、割合とは別に示す。（決定 D-26）
- **FR4.5** 結果は場面ごとの数と全体の割合で出す。1 件でも取り出せなければ失敗とし、場面を回せなかった時（Gemini の会話を起こせないなど）は「観測できず」として成功に数えない。（設計・実装の標準 S5・S8）
- **FR4.6** 試験は自社の機械の中で回し、外のサービスを使わない。S5 の使い捨ての Gemini の会話は、owner の決定を受けて CTO が起こす。（制約 C-11、決定 D-31）

### FR5 置き場所（P5）

- **FR5.1** 顧客ごとに、置き場所を自社（共通基盤の DB）か顧客の DB のどちらか一方に決める設定を持つ。（意図、決定 D-04・D-17、制約 C-02・C-17）
- **FR5.2** 席の記録は、その席の所属の顧客の置き場所にだけ書く。もう一方の置き場所や手元のファイルに写しを置かない。（制約 C-13・C-17）
  - 合格: 置き場所が顧客の DB の顧客の席が書いた記録は、共通基盤の DB と手元のファイルに 1 件も無い。
- **FR5.3** 置き場所の DB に届かない時、別の置き場所（手元の SQLite など）に書かず、書き込みは失敗として返す。席の起動は止めず、最初の文脈に「記憶に届かない」と出す。（角の一覧「保存先が使えない」、今の版の「PostgreSQL の指定があれば逃げない」）
- **FR5.4** 顧客の DB に置く形は、自社の機械に用意した顧客役の DB で確かめる。（決定 D-18、制約 C-11・C-19）
- **FR5.5** Kusabi は置き場所を Kusabi 専用の設定だけから読む。汎用の `DATABASE_URL` は読まない。（今のコードの読み解き `dependencies.md` の依存の注意）
  - 合格: 席の環境に別の製品用の `DATABASE_URL` だけがある時、Kusabi はその DB に表を作らず、設定が無いと名前を挙げて止まる。

### FR6 置き場所と読み書きできる者の一覧（P6）

- **FR6.1** 顧客を指定すると、その顧客の記憶の置き場所の DB と、読み書きできる者の一覧を、道具の応答で返す。画面は作らない。（意図の成功の条件、決定 D-33）
- **FR6.2** 一覧は、実際の DB の権限（DB の利用者と、その利用者が読み書きできる表）から作る。（Q6 = C）
- **FR6.3** 共通基盤の席の登録と並べ、食い違い（登録に無いのに読み書きできる者、登録にあるのに読み書きできない者）を示す。（Q6 = C）
  - 合格: 試験の環境で登録に無い DB の利用者に読み取りの権限を足すと、一覧の食い違いにその利用者が出る。
- **FR6.4** 一覧の応答に記憶の中身を含めない。（NFR1）
- **FR6.5** 権限を読めない時は「観測できず」と返し、空の一覧と区別する。（設計・実装の標準 S5）

### FR7 今の記録の移し（P7）

- **FR7.1** 今の記録の置き場所（席ごとの SQLite のファイルと PostgreSQL）を棚卸しし、置き場所ごと・持ち主（agent_id・project）ごとの件数を出す。（決定 D-22、制約 C-09）
- **FR7.2** owner が承認した対応表（今の agent_id・project → 共通基盤の席）に従って、共通基盤の DB へ移す。（決定 D-22、制約 C-08）
- **FR7.3** 対応表に無い記録は席に結ばず、「つながっていない記録」として件数を示す。推測で結ばない。（決定 D-22、固い決まり）
- **FR7.4** 移した後も、元の記録を消さず、変えない。（決定 D-22、固い決まり）
- **FR7.5** 移しは 2 回流しても 1 回と同じ結果になる。途中で止まっても、流し直せば欠けも重なりも出ない。（角の一覧「途中で止まる」「2 回流れる」）
- **FR7.6** 新しい置き場所へ切り替える前に、元の置き場所へ戻す手順を一度試す。（進め方の Deployment）

### FR8 会話の取り込み（P8）

- **FR8.1** Claude Code・Codex の会話の記録を、今の版と同じ伏せ字の処理をして、席の所属の顧客の置き場所に取り込む。（範囲 P8）
- **FR8.2** 隠れた推論と、開発者向けの指示の本文は取り込まない（今の版と同じ）。（範囲 P8、今の版の ingest_conversation_events）
- **FR8.3** 取り込みを 2 回流しても、同じ会話を 2 回入れない。（角の一覧「同じ物の繰り返し」）

## 非機能の要件

- **NFR1 外へ出さない**: 記憶の中身（決定・作業の状態・学び・会話）を、置き場所の DB の外に保存したり、外の API に送ったりしない。（固い決まり、制約 C-13、Q4 = C、Q5 = A）
  - 埋め込みを作らない。鍵が環境や鍵のファイルにあっても、Voyage AI などに送らない。探すのは DB の中の文字の検索だけ。
  - 手元の呼出しの記録（今の `~/.agent-memory/calls.log`）に、記憶の文（決定の文・作業の名前・知識の題など）を書かない。書くのは道具の名前と ID だけ。今の版は決定の文と作業の名前を書いている（`src/index.ts`）。
  - 取り出した記録を席の LLM の会話に入れることは、最初の版（社内の開発の席・自社の仕事）では、記憶を使うことそのものとして認める。（Q5 = A）
  - 合格: 鍵がある環境で記録を書いても、外への通信が 0 件で、手元のファイルに記憶の文が残らない。
- **NFR2 顧客の間の隔離**: どの読み取り・検索・一覧・取り込み・試験も、顧客をまたがない。（制約 C-15、Q3 = A、角の一覧「顧客の隔離」）
  - 合格: 顧客 X の席からのどの道具の呼出しにも、顧客 Y の記録が 1 件も入らない。
- **NFR3 席ごとの書き込みの権限**: 席は、自分の記録と自分の回復の設定だけを書き換えられる。今の `set_recovery_config` が任意の席の設定を書き換えられる作りは改める。（角の一覧「物ごとの権限」、今のコードの読み解き `code-quality-assessment.md`）
- **NFR4 起動の時の時間**: 起動の口の回復は、席の道具が起動の口に許す時間（native の起動の口では 7 秒）の中で終わる。間に合わない時は、回復を省いたことを出し、席の起動を止めない。（今の版の起動の口の期限、角の一覧「遅い・止まる呼出し」）
- **NFR5 失敗を隠さない**: 書き込みの失敗は失敗として返し、成功と言わない。試験・移し・一覧で「観測できず」を成功に数えない。（設計・実装の標準 S5・S8）
- **NFR6 戻せる形**: DB の作りの変更には、試した戻し方を付ける。変更の途中で、旧と新のコードが同じ作りで動く。適用は owner の決定の後に行う。（制約 C-07・C-16、設計・実装の標準 S6、保護面）
- **NFR7 消さない**: 参照される記録は物理的に消さず、状態で引退させる。（制約 C-16、設計・実装の標準 S1）
- **NFR8 秘密の扱い**: DB の資格情報は、環境か保護された置き場から読み、記録・応答・呼出しの記録に出さない。（角の一覧「秘密」、CLAUDE.md のセキュリティ）
- **NFR9 時刻と順序**: 時刻は UTC で時差つきで保つ。同じ時刻の記録は、決まった 2 つ目の鍵で順を決める。（角の一覧「時刻」「並び順」）
- **NFR10 試験の再現**: 場面の試験は、手順に書いた準備のほかは人の手を入れずに再現できる。PostgreSQL の試験は、最初は手元で回して結果を PR に載せ、置き場所の設計が固まったら CI に入れる（その時に owner の exact-head）。（進め方の Testing Posture）

## 制約

- 今の Kusabi と同じ TypeScript・Node.js・PostgreSQL で作り、新しい技術を足さない。（C-01）
- 自社の DB は共通基盤の DB と同じ所。共通基盤の DB に Kusabi の置き場を入れること、今の記録を移すことは、保護面として owner の決定が要る。（C-02・C-07）
- 席が誰かは共通基盤のエージェントの管理で決める。Kusabi は自前の席の一覧を持たない。（C-03）
- AUN との連動は今回は考えない。Claude Code・Codex の組込みの記憶は読み込みも書き出しもしない。外の記憶の製品は使わない。（C-04・C-05・C-06）
- 新しい費用・有料サービスは owner の決定なしに使わない。（C-11、固い決まり）
- 成功の指標は自社が管理できる範囲のものにする。場面の試験と一覧は自社で測れる。（C-12、team.md の Mandated）
- 記録は自社か顧客の DB の中で完結させる。C-13 の「外の LLM に記憶を出さない」は、「外の記憶の製品や LLM の道具の組込みの記憶に置かない」の意味で読む。席の LLM に渡すことは Q5 = A で扱う。（C-13、要約の確認）
- 個人情報保護法の確認は、顧客の仕事の記憶を置く段で行う。（C-14）
- Kusabi の新しい実装は停止中（T102）。この取り組みは設計の段階まで進め、実装は停止が解けてから。（C-10、決定 D-20・D-32）
- 進め方: 統合は merge commit、独立の監査の PASS の後に別の席が統合する、最初に薄い一本を作る、場面の試験を先に書く。（team-practices.md）

## 範囲の外

- 記憶の中身を AI が自動で要約・整理し直すこと（範囲の文書）
- 自社の DB と顧客の DB の間で記憶を移したり同期したりすること（範囲の文書、C-17）
- 人が記憶を直接見たり直したりする画面（範囲の文書、D-33）
- 他社のエージェント製品からの利用（範囲の文書）
- 全席の会話を横断して探すこと（範囲の文書、D-23）
- 会話の保存と取り直しの不具合（agent-memory#330）。今ある修理の流れで扱う（範囲の文書、D-25）
- 製品の中のエージェントが記憶を使う形、施設向けの新しいシステムを対象に加えること（範囲の文書）
- AUN との連動、Claude Code・Codex の組込みの記憶の読み書き（C-04・C-05）
- 埋め込みによる似た意味の検索。自社の中で動く仕組みは後の版で owner が決める（Q4 = C）
- 席の LLM に渡してはいけない物の決まり。顧客の仕事の記憶を置く版の前に作る（Q5 = A）
