このリポジトリの git の履歴・CI・展開の仕組み・CLAUDE.md・これまでの owner の決定から、今の進め方を下書き（`team-practices.md`）にしました。証拠だけでは決まらない所だけを聞きます。答えは、この先の実装の段階で守る「チームの進め方」として残ります。

## 証拠から読み取った今の進め方（聞き直さない）

- 変更ごとに branch を切り、main へ PR を出す。main への直接の commit はしない
- PR は独立の監査（devauditor）が PASS し、作者と別の席（suite-lead）が head の一致を確かめて統合する（T129）
- 保護面（DB の作りの変更・席の起動・展開・workflow・資格情報など）は owner の決定が無いと進めない
- commit の文は Conventional commits
- 展開は、統合された main から中身の決まった版を作り、席の束ごとに順に配る（失敗した束は元に戻す）
- 書き方の決まりは CLAUDE.md（TypeScript ESM、最大 800 行、絵文字なし など）
- Kusabi の実装は、決まった順が来て停止（T102）が解けてから（D-20・D-32）
