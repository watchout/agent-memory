# 作業の単位

- 入力: 部品の一覧（`inception/domain-design/components.md`）、決定の記録（`inception/domain-design/decisions.md` の ADR-001〜ADR-007）、要件（`inception/requirements-analysis/requirements.md`）、利用者の話（`inception/user-stories/stories.md`）、この段階の Q1〜Q2 と計画の承認
- この文書は単位の境目と中身まで。どの単位から作るか（順番）と、重要な経路は計画の段階（Delivery Planning）で決める。依存の形は `unit-of-work-dependency.md`、話との対応は `unit-of-work-story-map.md`。

## 単位の一覧

| Unit ID | Directory | 種類 | 大きさ | 置き方 | 主な部品 |
|---------|-----------|------|--------|--------|----------|
| U1 | u1-seat-memory-skeleton | service | M | 同じパッケージの中（MCP サーバーと起動の口） | Placement・SeatIdentity・MemoryRecords（決定だけ）・Recovery（起動の時の決定だけ）・ToolSurface・HostAdapters（Claude Code・Codex） |
| U2 | u2-memory-records | service | L | 同じパッケージの中 | MemoryRecords |
| U3 | u3-recovery-and-hosts | service | L | 同じパッケージの中 | Recovery・HostAdapters |
| U4 | u4-customer-placement | service | M | 同じパッケージの中 | Placement・SeatIdentity |
| U5 | u5-access-report | service | M | 同じパッケージの中（道具） | AccessReport |
| U6 | u6-conversation-ingest | service | M | 同じパッケージの中（道具とコマンド） | ConversationIngest |
| U7 | u7-legacy-migration | service | L | 同じパッケージの中（別のコマンド） | LegacyMigration |
| U8 | u8-scenario-harness | library | M | 同じパッケージの中（試験のコマンド。席には出さない） | ScenarioHarness |

- 置き方の全体: 今の版と同じく、1 つのパッケージ（wasurezu）の中に作り、席ごとに 1 つの MCP サーバーの process が動く（制約 C-01）。移しは別のコマンド、試験は試験のコマンド。置き場所の DB は、自社 = 共通基盤の DB、顧客 = 顧客ごとの DB（ADR-001）。
- DB の作り: 単位ごとに要る表を Kusabi の置き場に足す。どの変更にも試した戻し方を付け、変更の途中で旧と新のコードが同じ作りで動く形にする（NFR6）。本番の DB に当てるのは展開の段で owner の決定の後（制約 C-07）。

## U1 u1-seat-memory-skeleton（薄い一本）

- **中身**: 端から端まで通る最小の版。席の起動の設定で渡した Kusabi 専用の DB の設定で置き場所の DB につなぎ、共通基盤の確かめの関数で席を確かめ、決定を 1 件書き、再起動の後に別の種類の席の起動の口で同じ決定を読み戻す。（team.md の Walking Skeleton）
- **受け持ち**:
  - Placement: 専用の設定だけを読む・無い時は名前を挙げて止める・届かない時に別の置き場所へ逃げない・資格情報を出さない
  - SeatIdentity: DB の利用者から共通基盤の席・所属範囲・割り当てを確かめる・登録の無い席と所属の無い席を断る・記録に参照を付ける
  - MemoryRecords: 決定（Decision）だけを書く・読む（共通基盤の参照つき）
  - Recovery: 起動の時に、その席の有効な決定を回復の内容に入れる
  - ToolSurface: 決定を書く・読む道具、呼出しの記録に中身を書かない
  - HostAdapters: Claude Code と Codex の起動の口で回復を入れる。DB に届かない時は起動を止めず、そのことを出す
- **確かめ方**: 自社の機械の使い捨ての試験の DB で、試験の中で共通基盤 0.2・0.3 の置き場と Kusabi の置き場を作り、試験の席を登録して、終われば消す（Q2 = A）。使い捨ての試験の DB を手元の機械の PostgreSQL に作る時は、AUN の結合の試験の分とまとめて owner に伺う。
- **注意**: 決定以外の記録・仕事の ID・回復の全体は後の単位。U1 は後の単位が無くても単独で動く。

## U2 u2-memory-records

- **中身**: 記憶の核の残り全部。
- **受け持ち**:
  - 作業の状態（TaskState）と学び（Knowledge）の保存と読み出し
  - 仕事の ID の正規化（`owner/repo#番号`）と、仕事の ID での読み出し
  - 読める範囲の決まり（仕事の ID の無い記録は書いた席だけ・ID のある記録は同じ所属範囲の席・所属範囲をまたがない）
  - 同じ仕事への複数の席の作業の状態を上書きせずに残す
  - 書き換えの権限（ほかの席の記録を置き換えさせない）、記録を消さず置き換えと状態で引退させる
  - DB の中の文字の検索。埋め込みを作らず、Voyage AI を呼ばない（ADR-005）
- **注意**: 起動の設定の既定の仕事の ID を受け取る口は持つが、起動の口からの受け渡しは U3。

## U3 u3-recovery-and-hosts

- **中身**: 回復と起動の口の全体。
- **受け持ち**:
  - 回復の内容のすべて（進行中の作業・有効な決定・学び・最近の会話）と、回復の設定（席ごと・自分の物だけ書き換え）
  - 仕事の ID 1 回でまとめて返す束（RestartPack を含む）
  - 記録を「データ」として出すこと、入りきらない時の省いた件数と続きの取り出し方
  - 起動の口の期限（native の起動の口で 7 秒）と、間に合わない時に起動を止めない振る舞い
  - Gemini の起動の口、起動の設定の既定の仕事の ID の受け渡し（ADR-003）
  - 回復の質の記録
  - AUN の表を読まない（ADR-005）

## U4 u4-customer-placement

- **中身**: 顧客の DB の形で動くこと（ADR-001・ADR-002）。
- **受け持ち**:
  - 共通基盤の置き場と Kusabi の置き場の両方を持つ顧客の DB で、身元の確かめと保存を同じ transaction で行う
  - 顧客の席の記録が、その顧客の DB にだけあり、共通基盤の DB や手元のファイルに写しが無いこと
  - 顧客の DB の URL の資格情報を、失敗の文・起動の時の文脈・呼出しの記録に出さない
- **確かめ方**: 自社の機械の顧客役の DB（D-18）。顧客役の DB に共通基盤の置き場を入れるのは DB の作りの変更で、owner の決定の後。

## U5 u5-access-report

- **中身**: 置き場所と読み書きできる者の一覧（成功の条件の 2 つ目）。
- **受け持ち**:
  - 置き場所の DB の実際の権限から作る読み書きできる者の一覧（道具の応答、画面は作らない）
  - 共通基盤の席の登録と並べた食い違い（登録に無いのに読める者・登録にあるのに読めない者）
  - 応答に記憶の中身を入れないこと、権限を読めない時の「観測できず」

## U6 u6-conversation-ingest

- **中身**: 会話の記録の取り込みを、新しい置き場所で動かす（範囲 P8）。
- **受け持ち**:
  - Claude Code・Codex の会話の記録の伏せ字の処理、隠れた推論と開発者向けの指示の本文を外すこと
  - 席の所属の置き場所にだけ書くこと、同じ出来事を 2 回入れないこと
  - 回復のための最近の会話の読み出し（所属範囲をまたがない）
- **注意**: 会話の保存と取り直しの不具合（agent-memory#330）はここでは直さない。

## U7 u7-legacy-migration

- **中身**: 今の記録の移し（ADR-007）。
- **受け持ち**:
  - 席ごとの SQLite のファイルと今の PostgreSQL の棚卸し（読むだけ）
  - owner が承認した対応表に従う移し、対応表に無い記録の「つながっていない記録」の件数
  - 元を消さない・変えないこと、何度流しても同じ・途中で止まっても流し直せること
  - 切り替えの前に元の置き場所へ戻す手順の試し
  - 結べなかった古い記録の件数を試験の結果に渡す読み出しの口
- **注意**: 共通基盤の DB への移しを流すのは owner の決定の後（制約 C-07）。対応表の承認は owner。

## U8 u8-scenario-harness

- **中身**: 完了の判定の数を出す試験（ADR-006）。
- **受け持ち**:
  - 場面 S1〜S5 の試験。合成のデータで記録を作り、起動の口と MCP の道具の呼出しを本物の席と同じ形で再現して回す
  - 数え方（回復の内容に入っていた記録と、仕事の ID だけで道具を 1 回呼んで返った記録だけ。母数は試験の場面で作った記録だけ）
  - 結果の出し方（場面ごとの数・全体の割合・1 件でも欠ければ失敗・回せなかった場面は観測できず・結べなかった古い記録の件数は別）
  - 外のサービスを使わず、同じ準備で同じ結果になること
  - 本物の席での確かめ（席の種類ごとに 1 回）の証拠の置き場
- **注意**: 試験を先に書く進め方（team.md の Testing Posture）に合わせ、U1 にだけ依存する。U2・U3 ができるまでは、その場面の試験は失敗する。結べなかった古い記録の件数は U7 の移しの記録があれば読み、無い時は「移しをまだ流していない」と出す。S5 の使い捨ての Gemini の会話を起こすのは、その時に owner の決定を取る。
