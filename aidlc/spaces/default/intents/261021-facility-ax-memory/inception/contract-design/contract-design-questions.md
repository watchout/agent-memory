## 取り決めの範囲（聞き直さない所）

- 単位どうし（U1〜U8）は同じパッケージ（wasurezu）の中の TypeScript の関数の口でつながる。ネットワーク越しの呼出しは無い。単位の間の口は、部品の一覧の受け持ちのとおりに型で決める（ほかの単位は Kusabi の表を直接読み書きしない）
- 外に見える取り決めは 5 つ:
  1. 席に出す MCP の道具（席 = Claude Code・Codex・Gemini が使う。今の版は 17 個）
  2. 起動の口の出力（席の道具の起動の hook に返す回復の内容）
  3. 席の起動の設定（環境変数: 置き場所の DB・既定の仕事の ID など）
  4. DB の中の Kusabi の置き場（表と、保存・読み出しの口）
  5. 共通基盤の確かめの関数（onza の common 0.2・0.3。こちらは使う側。版を固定し、自動で最新に追従しない = 共通基盤 architecture.md §3）
- 移しのコマンドと試験のコマンドは、owner と開発の席が手元で使う
- 埋め込み（Voyage AI）と AUN の表の読み出しはやめる（ADR-005）

## Q3. DB の中の Kusabi の置き場への書き込みの口

共通基盤の決まりでは、製品の実行の DB の利用者には表の直接の書き換えを与えず、製品の保存の関数だけを出し、その関数の中で必ず共通基盤の確かめを呼びます（共通基盤 contract.md §5）。Kusabi の置き場をこの形にするかを決めます。DB の作りの決定なので、owner に伺います。

A. 席の DB の利用者には、Kusabi の保存・読み出しの関数だけを許し、表の直接の読み書きは許さない。関数の中で共通基盤の確かめを同じ transaction で呼び、所属範囲と読める範囲の決まりも関数の中で守る
B. 席の DB の利用者に表の直接の読み書きを許し、確かめと読める範囲の決まりはプログラム（MemoryRecords）の中で守る
C. Not yet defined（まだ決まっていない）
X. Other (please specify)

（勧め: A。共通基盤の決まりにそのまま合う。席が Kusabi のプログラムを通さずに DB を触っても、ほかの席や別の所属範囲の記録を読めない（NFR2・NFR3）。読み書きできる者の一覧（FR6）が、関数の実行の権限として実際の境目を表す。B は、プログラムを通さない読み書きを DB が止められず、一覧が実際の境目を表さない。A の負の面は、保存と読み出しの決まりを DB の関数で書く量が増えること。どちらでも、Kusabi の置き場を本番の DB に入れるのは展開の段で owner の決定の後）

（arc の勧め: A。会話の勧めと同じ。製品は共通の表を直接書き換えず、保存の関数の中で共通基盤の確かめを同じ transaction で呼ぶ、が共通基盤の決まり = common 0.2 の contract.md §5。席が Kusabi のプログラムを通さずに DB を触っても、ほかの席や別の顧客の記録を読めない。読み書きできる者の一覧も、関数の実行の権限として実際の境目を表せる = 要件 Q6 の「実際の DB の権限から作る」。DB の作りの決定なので Owner が決める）
