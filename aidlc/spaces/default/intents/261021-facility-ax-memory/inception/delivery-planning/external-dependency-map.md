# 外の依存（待つ物）の地図

- **Bolt**（ボルト）は、作る段を 1 回通して、1 つ以上の作業の単位を「動く物」まで仕上げる一区切り。
- ここに書くのは、この取り組みの作る手の外にあって、待つことになる物（owner の決定・ほかの製品・ほかの席の仕事）と、それを使う Bolt。
- 入力: 作る順の計画（`bolt-plan.md`）、取り決め（`inception/contract-design/contract-summary.md`）、範囲の文書の「先に要る owner の決定」（`ideation/scope-definition/scope-document.md`）、実現性の RAID（`ideation/feasibility/raid-log.md`）

## 地図

| 待つ物 | 持ち主 | 使う Bolt | 待つ間に止まる物 | 遅れた時の手当て |

| Kusabi の実装の停止（T102）の解除と、Kusabi の順番（Shirube・AUN → Onza → Tsumama → Kusabi） | owner（T102・D-32） | B1〜B8 のコードを書く段 | すべての Bolt のコードを書く段 | 単位ごとの設計の段までこの会話で進め、順番が来たらすぐ渡せる形で残す |

| 共通基盤 0.2・0.3 の配布物（onza の common、版を固定） | onza（共通基盤の持ち主）・arc | B1・B5・B6 | 席の確かめ・顧客の DB の形・一覧 | 固定する版（onza main 5beb404 か、その後の版か）を B1 の設計の段で決める（取り決めの未決の問い） |

## Bolt の前に伺う物

owner の決定が要る物を、それを使う Bolt の前にまとめて伺う。

| いつ | 伺う物 |
|------|--------|
| コードを書く段の初めの前（B1 の前） | 停止（T102）の解除と Kusabi の順番、使い捨ての試験の DB を作ること（AUN の分とまとめて）、網羅率を測る道具（組込みで足りない時）、CI に網羅率の確かめを足すこと、作る段の最初の区切りで使う確かめの命令、kusabi の席を AI-DLC の作業場で起動するか |
| B4 の前 | 使い捨ての Gemini の会話を起こすこと（CTO が起こす） |
| B4 か B5 の後 | CI に PostgreSQL の試験を足すこと |
| B5 の前 | 顧客役の DB に共通基盤の置き場を入れること |
| B8 の前 | 対応表の承認 |
| B8 の後（展開の段） | 本番の suite の DB に Kusabi の置き場を入れること・今の記録を移すこと・席ごとの DB の利用者の用意・席の展開 |
