# 作る順の理由とリスク

- **Bolt**（ボルト）は、作る段を 1 回通して、1 つ以上の作業の単位を「動く物」まで仕上げる一区切り。
- **薄い一本**（walking skeleton、Cockburn）は、本当の機能を入れる前に、部品どうしが端から端までつながって動くことを確かめる最小の版。
- 入力: 単位の依存（`inception/units-generation/unit-of-work-dependency.md`）、作業の単位（`inception/units-generation/unit-of-work.md`）、要件（`inception/requirements-analysis/requirements.md`）、利用者の話（`inception/user-stories/stories.md`）、部品の一覧（`inception/domain-design/components.md`）、取り決め（`inception/contract-design/contract-summary.md`）、実現性の RAID（`ideation/feasibility/raid-log.md`）、この段階の Q1〜Q2

## 使った考え方

点数をつける式（WSJF = 価値と急ぎ具合とリスクの減りを、作る大きさで割った値で並べる方法）は使わない。順は、前の段階で決まった 4 つの考え方で決まる。

1. **薄い一本を最初に**（Cockburn）: team.md の Walking Skeleton。B1 = U1
2. **試験を先に**: team.md の Testing Posture（成功の条件の場面の試験を、その場面を作る実装より先に書く）。B2 = U8
3. **いちばん不確かな所から**（Boehm のリスク先行）: 範囲の段の決定 D-28（P2 = 仕事の ID での引き継ぎを先に）。B3 = U2、続けて回復の全体 B4 = U3 で場面 S1〜S5 がそろう
4. **完了の判定の順**: 完了の判定の 2 つ目（置き場所と一覧、B5 = U4・B6 = U5）→ 4 つ目（会話の取り込み、B7 = U6）→ 3 つ目（今の記録の移し、B8 = U7）。移しは会話の取り込みが新しい置き場所で動いてから（U7 は U6 に依存）

## 依存の形との照らし合わせ

| 順 | 単位 | 依存先 | 依存先は前にあるか |
|----|------|--------|------------------|
| B1 | U1 | — | — |
| B2 | U8 | U1 | はい（B1） |
| B3 | U2 | U1 | はい（B1） |
| B4 | U3 | U2 | はい（B3） |
| B5 | U4 | U1 | はい（B1） |
| B6 | U5 | U4 | はい（B5） |
| B7 | U6 | U2 | はい（B3） |
| B8 | U7 | U2・U6 | はい（B3・B7） |

- 依存の形から外れる所は無い。U4（顧客の DB の形）は U1 の後ならいつでも作れるが、完了の判定の 1 つ目（場面の試験）を先にそろえるため B5 に置いた。

## 採らなかった並び

- **U4 を B3 にする**（顧客の DB の形もリスクが高い）: 共通基盤を顧客の DB に置く形は不確かだが、D-28 で P2（引き継ぎ）を先にすると決めてある。U4 は U1 の上に独立して作れるので、後に回しても手戻りが小さい。
- **U8（試験）を最後にする**: 試験を先に書く決まり（team.md）に合わない。試験が先にあれば、各 Bolt の済みの条件を同じ試験で確かめられる。
- **U7（移し）を U6 より前にする**: U7 は会話の出来事も移すので U6 に依存する（単位の依存の形）。

## リスク

| リスク | 起こりやすさ | 響き | 手当て |
|--------|------------|------|--------|
| 共通基盤 0.2・0.3 の確かめの関数を、Kusabi の保存と同じ transaction で呼ぶ形が、実際には組めない | 中 | 高 | 薄い一本（B1）で最初に確かめる。組めなければ部品の一覧に戻る |
| Kusabi の順番（D-32）と停止（T102）が長く続き、設計だけが進んで実装が始まらない | 中 | 中 | 単位ごとの設計の段までこの会話で進め、順番が来たらすぐ渡せる形で残す（実現性の R-02） |
| 使い捨ての試験の DB・顧客役の DB・使い捨ての Gemini の会話の owner の決定が来るまで、その Bolt の確かめが止まる | 中 | 中 | 決定の要る所を Bolt ごとに先に書き（`external-dependency-map.md`）、その Bolt の前にまとめて伺う |
| 今の記録の移しで、対応表に結べない記録が多く出る | 高 | 中 | 推測で結ばずに件数を出す（FR7.3）。母数に入れない（D-26） |

## 確かめの区切り（go / no-go）

- B1 の後: 薄い一本が owner の前で動いたら残りの Bolt に進む。動かなければ、部品の一覧と取り決め（C4・C5）に戻る。
- B4 の後: 場面 S1〜S5 の試験が 100% になったら、完了の判定の 1 つ目がそろう。
- B8 の後: 完了の判定の 4 つがそろったら、展開の段（本番の共通基盤の DB・席の展開）に進む。展開は owner の決定を受けてから。
