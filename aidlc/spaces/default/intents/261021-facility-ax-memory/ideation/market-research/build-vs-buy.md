# 作るか借りるかの文書 — 席の記憶の置き場

前の段階の意図の文書（`ideation/intent-capture/intent-statement.md`）で決めた条件を満たすために、作るか、借りるか、組み合わせるかを整理します。比べた結果は比較の文書（`competitive-analysis.md`）、外の流れは流れの文書（`market-trends.md`）にあります。

## 方針（決定済み）

- 今の Kusabi を土台に自前で作る。外の記憶の製品は使わず、公開の仕組みは考え方の参考にとどめる。（質問 Q4 の答え。根拠として iyasaka-arc#49 6328010677 の決定 1「Kusabi は施設向けの管理の AX システムの記憶の層として残す。自社か顧客の DB で完結、外の記憶の製品は使わない」）
- 最初の版は社内の開発の席で使い始め、組込みの記憶は比べる相手にとどめ、席の記憶の正は Kusabi に置く。（質問 Q7 の答え。iyasaka-arc#49 6329622282 で、決定 4「社内の開発の席の記憶は当面、組込みで足りる」の一部が変わった）
- この文書は、決まった方針を比べた結果で確かめ直すもので、方針を変えるものではない。

## 比べた結果で確かめる

評価の目安: +2 = 作る側に強く傾く／0 = どちらでもない／-2 = 借りる側に強く傾く。

| 観点 | 作る（今の Kusabi を土台） | 借りる（外の記憶の製品） | 評価 |
|------|---------------------------|-------------------------|------|
| 中核かどうか | 施設向けの AX システムの記憶の層として、自社の差を出す所（決定 1） | 汎用の記憶。自社の差にはならない | +2 |
| 条件 A（自社か顧客の DB に置く） | 自社の DB にはもう置いている。顧客の DB は試験の環境で確かめる段（意図の文書） | Mem0 は自前の Postgres に置けるが、既定で外の LLM へ中身を送る。Graphiti は LLM が必須（流れの文書） | +1 |
| 条件 B（種類の違う AI の席から同じ記憶） | 今の版は「同じエージェント／プロジェクトの範囲」で、またぐ連携は未実装。作る必要がある | 種類をまたぐ形を満たすものは見つからなかった（比較の文書） | +1 |
| 条件 C（交代・再起動の後に取り出す） | 回復の道具はあるが、自動でつながる所と回復の質の測定は未実装（点検 v1） | 公開の文書では判定できなかった | 0 |
| 条件 D（顧客ごとの置き場所と読み書きの一覧） | 未確認。作る必要がありうる | Mem0 に監査記録があるが、顧客ごとの一覧は確かめられなかった | 0 |
| 時間 | 今の版を直して足す。Kusabi の新しい実装は T102 で止めたまま（iyasaka-arc#49 6329622282） | 入れるのは早いが、条件 A・B を満たすための作り込みが別に要る | -1 |
| 保守 | 自社で持ち続ける | 相手の都合に左右される。Letta は自前で動かす旧来の版の保守をやめている（比較の文書） | +1 |
| 既にある資産 | Kusabi v0.3.0 が社内で動いている。会話の保存と取り直しの不具合（agent-memory#330）が開いたまま（点検 v1） | — | +1 |

- 合計は作る側に傾き（+5）、決まった方針（作る）と食い違わない。
- ただし「時間」と「既にある資産の不具合」は作る側の弱み。最初の版の範囲を決める次の段階（実現性と制約）で扱う必要がある。

## 借りる考え方（公開の仕組みから参考にする所）

| 参考にする所 | どこから | 何に効くか |
|-------------|---------|-----------|
| 記憶の索引を毎回の会話の最初に読み、大きさの上限を決める（最初の 200 行か 25KB） | Claude Code の auto memory | 条件 C（再起動の後に自分で再開する）。読む量の上限 |
| 記憶を足す時に、そのまま保存するか抜き出すかを選べる | Mem0 の記憶の追加 | 条件 A（外の LLM を呼ばない保存の道を持つ） |
| 呼び出しの監査記録と、利用者ごとの鍵 | Mem0 の自前で動かす版 | 条件 D（読み書きできる者の一覧） |
| 記憶のかたまりを複数のエージェントで分け合う | Letta | 条件 B（席をまたいで同じ記憶を使う） |
| 席への指示を書く共通の形（AGENTS.md）と、外の機能を呼ぶ共通のつなぎ方（MCP） | Agentic AI Foundation（流れの文書） | 条件 B（席の種類が増えても作り直しを少なくする） |

## 確かめていないこと

- 「時間」の評価（-1）は見込みで、作る量を見積もっていない。次の段階（実現性と制約）で見積もる必要がある。
- LLM の呼出しの扱い（記憶を足す時に AI で要約するか）は、iyasaka-arc#49 6328010677 で「含まないもの」とされている。意図の文書は「AI による自動整理」を最初の版でやらないとしている。
