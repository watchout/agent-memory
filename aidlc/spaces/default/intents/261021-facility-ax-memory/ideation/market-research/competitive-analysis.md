# 比較の文書 — 席の記憶を保つ仕組みの比べ合わせ

前の段階の意図の文書（`ideation/intent-capture/intent-statement.md`）で決めた「席の記憶を自社か顧客の DB に保ち、どの席も続きから再開できる」を満たせるかで、既製のものと社内の仕組みを比べます。比べ方は、Kusabi の点検 v1（iyasaka-arc#57 6327895152）を出発点にし、足りない所を公開の情報で確かめました（質問 Q6）。情報は 2026-10-22 に確認したものです。

## 言葉の説明

- **席**: 自社の席として動く AI（Claude・Codex・Gemini など種類を問わない）。記憶の持ち主。
- **MCP**: AI の道具が外の機能を呼ぶための共通のつなぎ方。Claude Code などの席が Kusabi を呼ぶ時にも使う。
- **外の LLM**: OpenAI などの事業者が提供する AI。記憶の中身をそこへ送ると、自社・顧客の管理の外に出る。

## 違いを出す所（Kusabi が持つべき所）

- 今回調べた範囲では、4 つの条件（A〜D）をそろって満たす相手は無かった。特に「種類の違う AI の席から同じ記憶を使う」（B）と「顧客ごとの置き場所と読み書きの一覧」（D）を両方満たすものは見つからなかった。（上の表）
- AI の道具の組込みの記憶（E1・E2）は、1 つの席が同じ機械で会話を続けるには足りるが、機械をまたぐことも、種類の違う席に引き継ぐこともしない。意図の文書のきっかけ（社内の開発で席が記憶を失って再開できない）のうち、担当の交代の部分には届かない。
- 外の記憶の製品（M1〜M3）は自前の DB に置けるものがあるが、多くは記憶を足す時に外の LLM を呼ぶ既定になっており、そのままでは「自社・顧客の管理の外に出さない」（A）と食い違いやすい。
- したがって Kusabi の違いは「自社か顧客の DB の中だけで完結し」「席の種類を問わず」「決定・作業の状態・学びを交代と再起動の後に取り出せ」「顧客ごとに置き場所と読み書きの一覧を出せる」の 4 つが同時にそろうこと、と置く。（意図の文書の成功の測り方と同じ）

## 確かめていないこと

- M1〜M4 の条件 C（決定・作業の状態・学びを交代と再起動の後に取り出せるか）は、公開の文書だけでは判定できなかった。判定には実際に動かす試しが要る。
- Kusabi の今の版の条件 D（顧客ごとの一覧）が、今あるもので出せるか。
