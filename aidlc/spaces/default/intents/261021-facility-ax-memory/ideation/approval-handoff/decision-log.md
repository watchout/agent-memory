# 決定の記録（Ideation の段階）

入力: 意図の文書（`ideation/intent-capture/intent-statement.md`）、関係者の一覧（`ideation/intent-capture/stakeholder-map.md`）、範囲の文書（`ideation/scope-definition/scope-document.md`）、能力の一覧（`ideation/scope-definition/intent-backlog.md`）、各段階の質問の答え。決めたのはすべて owner。多くの段階で、答えは arc の下書きを owner が確定した。

## 意図の確認と整理

| ID | 決定 | 出典 |
|----|------|------|
| D-01 | 記憶の持ち主は席（自社の席として動く AI。種類を問わない）。効く先は製品ではなく席 | 意図の Q14、要約の確認での owner の訂正 |
| D-02 | 解決する問題は、区切りで記憶を失う／担当の交代で経緯が途切れる／記憶が自社・顧客の管理外にある、の 3 つ | 意図の Q2 |
| D-03 | Onza と OmotenasuAI は記憶を使う側ではなく、席が仕事をする対象。施設向けの新しいシステムは後で加える | 意図の Q1・Q11 |
| D-04 | 置き場所は、顧客ごとに自社か顧客の DB のどちらか一方を最初の版から選べる。同じ記憶を 2 か所に置かないので同期は要らない | 意図の Q4・Q16・Q17 |
| D-05 | まず得をするのは自社の席と、席に仕事を任せる owner・開発運用。施設のスタッフ・運営会社・営業への効き目は間接的で、最初の版の目的に入れない | 意図の Q3・Q15 |
| D-06 | 成功の測り方は、担当交代と再起動の場面を決めた試験で取り出せる割合 100%、顧客ごとの置き場所と読み書きの一覧を出せること | 意図の Q5・Q12 |
| D-07 | 最初の版でやらないこと: AI による自動整理、自社と顧客の DB の間の移行・同期、人が記憶を見る・直す画面、他社製品からの利用 | 意図の Q6 |
| D-08 | 使い始めは社内の開発の席で自社の DB から。顧客の DB に置く形は試験の環境で確かめる | 意図の Q13 |
| D-09 | 対象は社内の開発の席すべて（AUN・Shirube などの開発の席も）。顧客の DB の選択は顧客の仕事の時だけ | 意図の Q18 |
| D-10 | 範囲と優先度は owner が決める。報告は段階ごとにこの会話で、決まったことは iyasaka-arc#49 に記録し agent-memory#330 に写す | 意図の Q9・Q10 |
