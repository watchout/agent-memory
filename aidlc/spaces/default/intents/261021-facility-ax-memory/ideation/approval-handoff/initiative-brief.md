# 取り組みのまとめ — 席の記憶を自社か顧客の DB に保ち、どの席も続きから再開できる

入力: 意図の文書（`ideation/intent-capture/intent-statement.md`）、関係者の一覧（`ideation/intent-capture/stakeholder-map.md`）、比較の文書（`ideation/market-research/competitive-analysis.md`）、実現性の見立て（`ideation/feasibility/feasibility-assessment.md`）、制約の一覧（`ideation/feasibility/constraint-register.md`）、範囲の文書（`ideation/scope-definition/scope-document.md`）、能力の一覧（`ideation/scope-definition/intent-backlog.md`）、体制の見立て（`ideation/team-formation/team-assessment.md`）、この段階の質問 Q1〜Q3 の答え。画面案の段階は、人が見る画面を作らないため省いた。

## 意図と問題

- 席（自社の席として動く AI。Claude・Codex・Gemini など種類を問わない）の記憶を、自社か顧客の DB の中に保ち、担当が替わっても、再起動や文脈の圧縮の後でも、どの席も続きから仕事を再開できるようにする。（意図の文書）
- 今は、席が区切りで記憶を失い、担当の交代で経緯が途切れ、席の記憶が自社・顧客の管理の外にある。社内の開発で、席が記憶を失って仕事を再開できない事態が繰り返されている。（意図の文書）

## 市場で確かめたこと

- 今回調べた範囲では、4 つの条件（自社か顧客の DB に置ける／種類の違う席から同じ記憶を使える／交代・再起動の後に取り出せる／顧客ごとに置き場所と読み書きの一覧を出せる）をそろって満たす既製のものは無かった。（比較の文書）
- 方針は、今の Kusabi を土台に自前で作る。外の記憶の製品は使わず、公開の仕組みは考え方の参考にとどめる。（作るか借りるかの文書）

## 実現性とリスク

- 条件付きで作れる。作る量はまだ見積もっていない。（実現性の見立て）
- 先に越える関門: 共通基盤の DB への置き場の owner の決定、今の記録を移す時の対応表の承認、Kusabi の新しい実装の停止（T102）の解除。（実現性の見立て）
- いちばん大きいリスクは、種類の違う席の間の引き継ぎ（「同じ仕事」の見分け方）。リスク R-01〜R-07 は手当てのとおり受け止めて進める。（リスクの一覧、この段階の Q1）

## 範囲の線

- 入るもの: P1 席の見分け／P2 種類の違う席の間の引き継ぎ／P3 交代・再起動の後の取り出し／P4 試験（Claude・Codex・Gemini。Gemini は使い捨ての会話）／P5 置き場所の選択／P6 置き場所と読み書きの一覧（画面ではなく道具の応答として出す）／P7 今の記録の移し／P8 会話の取り込み。（範囲の文書、画面案の段階での owner の指示）
- 入らないもの: AI による自動整理、自社と顧客の DB の間の同期、人が記憶を見る・直す画面、他社製品からの利用、全席の会話の横断検索、#330 の修理（別の修理の流れ）など。（範囲の文書）
- 完了: 試験で取り出せる割合 100%（母数は試験の場面の記録だけ）と、顧客ごとの置き場所と読み書きの一覧がそろった時。期日は無い。（範囲の文書）

## 流れの絵

- 画面案は作らない。価値の流れは範囲の文書の図のとおり: 席が書く → Kusabi が顧客ごとに選んだ置き場所に保つ → 担当を替えた席・再起動した席が取り出す → 人が説明し直さずに続きが始まる → owner と開発運用の仕事が止まらない。（範囲の文書）

## 体制

- 決定・承認・保護面 = owner、設計 = arc、配車と統合 = suite-lead、実装 = kusabi の席、独立の監査 = devauditor、試験の使い捨ての Gemini の会話 = CTO（owner の決定を受けて）。（体制の見立て）
- 決まったことは arc が iyasaka-arc#49 に記録し、agent-memory#330 に写す。（この段階の Q3）
- 関係者のうち顧客企業の情報システムの担当と現場スタッフの合意は、顧客の DB に置く形を顧客に出す段で取る。（関係者の一覧、この段階の Q2）
- Kusabi の実装は、停止（T102）が解け、決まった順（Shirube・AUN → Onza → Tsumama → Kusabi）が来てから。停止の間は設計の段階まで進める。（体制の見立て）

## 進めるかの勧め

- **進める（条件つき）。** Inception（要件から）へ進み、停止の間は設計の段階まで進める。実装の開始は、停止の解除と、共通基盤の DB への置き場の owner の決定を待つ。
- 次の段階で最初に扱うこと: 種類の違う席の間で「同じ仕事」を何で見分けるか（P2）、試験の場面、会話の取り込み（P8）を完了の判定に含めるか。

## 確かめていないこと

- 作る量の見積もり（実現性の見立て）。
- 会話の取り込み（P8）を完了の判定に含めるか（範囲の文書）。
