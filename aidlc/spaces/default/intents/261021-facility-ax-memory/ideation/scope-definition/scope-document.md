# 範囲の文書 — 最初の版で作るもの、作らないもの

入力: 意図の文書（`ideation/intent-capture/intent-statement.md`）、実現性の見立て（`ideation/feasibility/feasibility-assessment.md`）、制約の一覧（`ideation/feasibility/constraint-register.md`）、この段階の質問 Q1〜Q8 の答え。

## 目的

- 席（自社の席として動く AI。Claude・Codex・Gemini など種類を問わない）の記憶を、自社か顧客の DB の中に保ち、担当が替わっても、再起動や文脈の圧縮の後でも、どの席も続きから仕事を再開できるようにする。（意図の文書）
- まず得をするのは、自社の席と、席に仕事を任せる owner・開発運用。施設のスタッフ・運営会社・営業への効き目は間接的で、最初の版の目的に入れない。（意図の文書）

## 範囲に入るもの（最初の版）

| ID | 能力 | 出典 |
|----|------|------|
| P1 | 席が誰かを、共通基盤のエージェントの管理に合わせて見分ける | 制約 C-03 |

| P3 | 担当交代と再起動の後に、決定・作業の状態・学びを取り出す。人が経緯を説明し直さずに、席が自分で続きを始められる | 意図の文書の成功の条件 |

| P7 | 今の記録を棚卸しし、対応表（owner が承認）を通して共通基盤の DB へ移す。元は消さない。対応の無い記録は推測でつながない | 実現性の質問 Q8、制約 C-08・C-09 |
| P8 | 会話の取り込み（Claude Code・Codex の会話の記録を Kusabi に入れる。今の版にある機能） | 質問 Q1 |

## 完了の判定

- 最初の版は、次の 2 つがそろった時に完了とする。（質問 Q5）
  1. 担当交代と再起動の場面を決めた試験で、決定・作業の状態・学びを取り出せる割合が 100%。
  2. 顧客ごとに、記憶の置き場所の DB と、読み書きできる者の一覧を出せる。
- 「100% 取り出せる」の母数は、試験の場面で作った記録だけ。今の記録は数えず、対応表で結べなかった古い記録の件数は別に示す。（質問 Q4）
- 動かせない期日は無い。完了の条件がそろった時を完了とする。（質問 Q7）

## 進める順番の方針

- いちばん不確かな所から進める。種類の違う席の間で同じ仕事を見分ける所（P2）を先に決める。（質問 Q6）
- 具体の並びは、能力の一覧（`intent-backlog.md`）に案を置き、後の計画の段階で決める。

## 確かめていないこと
