## 本人と権限

| ID | 要件 | 確かめ方 |
|----|------|----------|
| NFR2.1 | 決定は、書いた席と同じ席・同じ所属範囲の席からしか読めない（U1 の決定は仕事の ID を持たない） | 試験で、別の席の DB の利用者から決定を読むと 1 件も返らない |
| NFR3.1 | 席は、共通基盤で確かめた自分の席としてだけ決定を書ける。引数や環境の値でほかの席として書けない | 試験で、引数や `AGENT_MEMORY_AGENT_ID` にほかの席の名前を入れても、記録の seat_ref は自分の席になる |
| NFR8.1 | 席ごとに DB の利用者を分け、パスワードは SCRAM-SHA-256 で確かめる。手元の機械の外の DB につなぐ時は、確かめつきの TLS を使う | 試験の DB の利用者の作り方と、外の DB の設定の決まり |
| NFR8.2 | 席の DB の利用者には、Kusabi の公開関数の実行だけを許し、Kusabi の表を直接読み書きさせない。関数は持ち主の権限で動き、探す場所（search_path）を固定する | 試験で、席の DB の利用者から Kusabi の表を直接読もうとすると断られる |

## 秘密と外への送り出し

| ID | 要件 | 確かめ方 |
|----|------|----------|
| NFR8.3 | 資格情報（DB の URL のパスワードなど）を、失敗の文・起動の時の文脈・道具の応答・呼出しの記録に出さない。資格情報は環境から読む | 試験で、パスワードつきの URL で DB を止めた時の失敗の文・起動の文脈・呼出しの記録にパスワードの文字列が無い |
| NFR1.1 | 呼出しの記録には、道具の名前・記録の ID・時刻・結果だけを書き、決定の文・作業の名前・学びの題を書かない | 試験で、決定を書いた後の呼出しの記録に決定の文が無い |
| NFR1.2 | U1 の共通基盤の形の道のりで、外のサービス（Voyage AI など）を呼ばない | 試験で、鍵がある環境でも外への通信が 0 件 |

## 脅かしの見立て

- **ほかの席になりすます**: 席は DB の利用者（`session_user`）から共通基盤で確かめる（BR2.1）。渡された値を本人の証拠にしない。
- **Kusabi のプログラムを通さない読み書き**: 席の DB の利用者に表の権限を与えない（NFR8.2）。関数の中で確かめる。
- **同じ OS の利用者で動く席どうし**: 手元の機械では席ごとの隔離が弱いことは受け入れ済み（iyasaka-arc#49 6290511960）。一覧（U5）がその食い違いを出す。
- **呼出しの記録や失敗の文からの漏れ**: 中身と資格情報を書かない（NFR1.1・NFR8.3）。
