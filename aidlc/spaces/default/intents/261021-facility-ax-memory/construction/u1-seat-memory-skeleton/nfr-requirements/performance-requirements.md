# U1 の速さの要件

- 入力: 要件（`inception/requirements-analysis/requirements.md` の NFR4）、U1 の振る舞いの仕様（`construction/u1-seat-memory-skeleton/functional-design/functional-spec.md` の W2〜W4）、この段階の質問の答え
- 測る場所: この Mac の DB（試験は試験のたびに立ち上げる専用の PostgreSQL 17）

## 時間の上限

| ID | 要件 | 目標 | 超えた時 |
|----|------|------|----------|
| NFR4.1 | 起動の口の回復の全体の時間 | 7 秒以内（native の起動の口の期限） | 回復を打ち切り、memory_status を出して席の起動を続ける |
| NFR4.2 | 起動の口の、置き場所の DB への接続 | 2 秒以内 | memory_status=unreachable、回復の内容は空、起動を続ける |
| NFR4.3 | 起動の口の、席の確かめと決定の読み出し | 3 秒以内 | 回復を打ち切り、起動を続ける |
| NFR5.2 | 道具の 1 回の呼出しの DB の処理 | 5 秒以内 | 失敗として返す（成功と言わない） |

## 道具の速さ

| ID | 要件 | 目標 | 測り方 |
|----|------|------|--------|
| NFR4.4 | 決定を書く・読む道具の速さ | 1 つの席の決定が 1 万件までの時、95% が 500 ミリ秒以内 | 試験の DB に合成の決定を 1 万件入れ、書く・読むを 100 回ずつ流して 95 番目の値を見る |

- 要件の前提 AS7（速さの数値の要件は置かない）は「製品の利用者に約束する数値を置かない」と読み、ここの数値は NFR4.1（起動の時の期限）を守るための作る側の目安として置く。
