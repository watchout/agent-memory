# U1 の規模の要件

- 入力: 要件（`inception/requirements-analysis/requirements.md` の前提 AS7）、U1 の速さの要件（`performance-requirements.md` の NFR4.4）

## 見込む量

| ID | 要件 | 値 |
|----|------|----|
| NFR4.5 | 席の数と記録の量の見込み | 社内の開発の席（数十）。1 つの席の決定は 1 万件まで。この量で NFR4.1〜NFR4.4 を満たす |
| NFR4.6 | 1 つの MCP サーバーの process が持つ DB への接続 | 1 本。接続をまとめて持つ仕組み（pool）は使わず、別の席の接続と混ぜない（共通基盤 architecture.md §4 の「接続プールは別主体の接続を混用しない」） |

## 増えた時

- 1 つの席の決定が 1 万件を超えたら、回復の内容は件数の上限（U3 の回復の設定）で切り、省いた件数を出す（U3 の受け持ち）。U1 では上限を設けず、試験の量は 1 万件まで。
- 席の数が増えても、席ごとに process と接続が 1 本ずつ増えるだけで、席どうしは待ち合わせない。
