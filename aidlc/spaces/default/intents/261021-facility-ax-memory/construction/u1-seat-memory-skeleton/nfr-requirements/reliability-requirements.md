# U1 の信頼の要件

- 入力: 要件（`inception/requirements-analysis/requirements.md` の NFR5・NFR6・NFR7）、U1 の決まり（`construction/u1-seat-memory-skeleton/functional-design/rules.md` の BR1.4・BR1.5・BR3.3・BR4.2）

## 失敗の扱い

| ID | 要件 | 確かめ方 |
|----|------|----------|
| NFR5.1 | 書き込みの失敗は、失敗の名前つきで返し、成功と言わない | 試験で、DB を止めた時の書き込みが placement_unreachable を返す |
| NFR5.3 | 置き場所の DB に届かない時、ほかの置き場所（手元の SQLite・別の DB・手元のファイル）に書かない。DB が戻れば、Kusabi を起動し直さずに書ける | 試験で、DB を止める → 書く（失敗・手元に何も無い）→ DB を戻す → 書く（通る） |
| NFR5.4 | 共通基盤の確かめと決定の保存は 1 つの取引。どちらかが失敗したら、どちらも残さない | 試験で、確かめが失敗する席として書くと、決定が 1 件も増えない |
| NFR5.5 | 起動の口では、DB に届かない・登録が無い・期限に間に合わない時も、席の起動を止めない | 試験で、それぞれの場合に起動の口が席の起動を返す |

## 作りの変更と記録の保ち方

| ID | 要件 | 確かめ方 |
|----|------|----------|
| NFR6.1 | U1 が Kusabi の置き場に足す作りの変更（決定の表と関数）は、試した戻し方を持つ。戻した後、変更の前のコードの試験が通る | 試験で、当てる → 戻す → 前の試験が通る |
| NFR7.1 | 決定は物理的に消さない（U1 には消す道具も関数も無い） | 関数の一覧に消す物が無いことを試験で確かめる |

## 落ちた時の戻り方

- U1 は試験の DB と本物の会話の確かめだけで動き、本番の DB には入らない。本番に入れるのは展開の段で owner の決定の後（制約 C-07）。
- MCP サーバーの process が落ちても、書き込みは取引の単位で残るか残らないかのどちらかで、途中の物は残らない（NFR5.4）。
