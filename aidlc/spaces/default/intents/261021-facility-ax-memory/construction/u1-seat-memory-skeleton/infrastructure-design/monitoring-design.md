# U1 の観測の仕組み

- 入力: U1 の観測の設計（`construction/u1-seat-memory-skeleton/nfr-design/observability-design.md`）、速さの設計（`performance-design.md`）
- U1 は本番に入らないので、ここに書くのは試験と本物の会話の確かめで見る物。外の監視のサービスは使わない（NFR1.2）。

## Metrics & KPIs

| Metric | Source | Threshold | Why it matters |
|--------|--------|-----------|----------------|
| 起動の口の回復の時間 | 起動の口の試験 | 7 秒以内（NFR4.1） | 席の起動を止めないため |
| 決定を書く・読む道具の 95 番目の時間 | 速さの試験（1 万件・100 回ずつ） | 500 ミリ秒以内（NFR4.4） | 起動の時の期限を守るための目安 |
| 薄い一本の試験の結果 | 試験の命令 | 決定が回復の内容に出る・負の確かめがすべて通る | 薄い一本が端から端まで動く証拠 |
| 行の網羅率 | 網羅率の道具（Node の組込みか c8） | 80% 以上（team.md） | 統合の前の床 |
| 共通基盤の写しの sha256 | 写しの試験 | 3 つとも一致 | 写しが監査済みの版のまま |
| 外への通信の数 | 試験の中の観測 | 0 件（NFR1.2） | 記憶の中身を外へ出さない |

## Alerts

| Alert | Condition | Severity | Routes to |
|-------|-----------|----------|-----------|
| 試験の失敗 | 試験の命令が 0 以外で終わる | 統合を止める | PR の作者（kusabi の席）と監査（devauditor） |
| 写しの不一致 | sha256 が一致しない | 統合を止める | 同上。共通基盤の版を上げるなら別の PR |
| 網羅率の不足 | 80% に届かない | 統合を止める（CI に入れた後） | 同上 |

- 本番の見張り（席の起動の失敗の数・DB に届かない数など）は、展開の段で決める。

## SLIs / SLOs

| SLI | SLO target | Measurement window |
|-----|------------|--------------------|
| 起動の口が 7 秒以内に席の起動を返す割合 | 100%（試験の場面で） | 試験の 1 回ごと |
| 決定を書く・読む道具の 500 ミリ秒以内の割合 | 95% 以上 | 速さの試験の 1 回（100 回ずつ） |

## Logs & Tracing

- 呼出しの記録は手元の `~/.agent-memory/calls.log` に 1 行 1 件の JSON（道具の名前・記録の ID・時刻・結果）。集めて送る仕組みは無い。
- 道具の失敗は失敗の名前を文の先頭に置く。起動の口の出力には memory_status を出す。追跡（tracing）は使わない。席・時刻・記録の ID で十分に追える。
- 見る画面（dashboard）は作らない（最初の版は画面を作らない、D-33）。
