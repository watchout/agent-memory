# U1 の信頼の設計

- 入力: 信頼の要件（`construction/u1-seat-memory-skeleton/nfr-requirements/reliability-requirements.md` の NFR5.1・NFR5.3〜NFR5.5・NFR6.1・NFR7.1）、決まり（`construction/u1-seat-memory-skeleton/functional-design/rules.md` の BR1.4・BR1.5・BR3.3・BR4.2）

## 失敗の時の振る舞い

| 場面 | 振る舞い | 要件 |
|------|----------|------|
| 道具の呼出しで DB に届かない | placement_unreachable を返す。手元の SQLite・別の DB・手元のファイルに書かない。接続を捨て、次の呼出しでつなぎ直す | NFR5.1・NFR5.3 |
| DB が戻った | 次の呼出しで新しくつなぎ、そのまま書ける。Kusabi の起動し直しは要らない | NFR5.3 |
| 確かめか保存の失敗 | 1 つの関数の呼出し = 1 つの取引なので、決定は増えない | NFR5.4 |
| 起動の口で届かない・登録が無い・期限に間に合わない | memory_status を出し、回復の内容を空にして、席の起動を返す | NFR5.5 |

- 再送（retry）はしない。道具の呼出しの失敗は席に返し、席が決める。同じ決定が 2 件になるのを防ぐ鍵は取り決めの未決の問い（U2 で決める）。
- 回路を遮る仕組み（circuit breaker）は置かない。席ごとに 1 本の接続で、失敗はその席にしか響かない。

## 作りの変更の当て方と戻し方

- Kusabi の置き場に足す変更（置き場・役割・決定の表・索引・公開関数）は、当てる版と戻す版を対で持つ（NFR6.1）。
- 試験で、当てる → 戻す → 変更の前のコードの試験が通る、を確かめる。
- 当てる版は何度流しても同じ結果になる形で書く（同じ物があれば作らない）。
- 消す関数は作らない（NFR7.1）。関数の一覧に消す物が無いことを試験で確かめる。

## 落ちた時

- MCP サーバーの process が落ちても、取引の途中の物は残らない（NFR5.4）。
- U1 は試験の DB と本物の会話の確かめだけで動く。本番の DB の守り（控え・戻し）は展開の段で決める。
