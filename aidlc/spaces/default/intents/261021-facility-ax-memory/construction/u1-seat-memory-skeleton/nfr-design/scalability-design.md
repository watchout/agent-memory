# U1 の規模の設計

- 入力: 規模の要件（`construction/u1-seat-memory-skeleton/nfr-requirements/scalability-requirements.md` の NFR4.5・NFR4.6）、速さの設計（`performance-design.md`）

## 広がり方

- 席ごとに MCP サーバーの process が 1 つ動き、process ごとに DB への接続を 1 本だけ持つ（NFR4.6）。席が増えると process と接続が 1 本ずつ増え、席どうしは待ち合わせない。
- 接続をまとめて持つ仕組み（pool）は使わない。別の席の接続と混ぜない（共通基盤 architecture.md §4）。
- 席は数十の見込み（NFR4.5）。PostgreSQL の同時接続の上限（既定 100）の中に収まる。席が 100 に近づいたら、接続の上限の見直しを展開の段の確かめに入れる。

## 量の見込み

- 決定は 1 つの席につき 1 万件までを U1 の試験の量とする（NFR4.5）。読み出しは索引で新しい順に読み、件数の上限で切るので、件数が増えても 1 回の読み出しの量は増えない。
- 表を所属範囲や席で分けて置くこと（分割）はしない。量が 1 万件を大きく超える見込みが出たら、その時に分け方を決める。
