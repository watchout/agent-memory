# 戻しの手順 — 会話の切り直し（261110-session-rotation）

`cd-config.md` の各段に対応する戻し。どの戻しも、戻す前に今の状態を証拠に取り、戻した後に読み戻す。DB は変えていないので、DB の戻しは無い。

**第 2 版（2026-11-12）**: 第 2 版は S3 と S4 を 1 回の操作で行い（Q7 = B）、backup は 1 つ。戻した後の状態は「旧い版 `1b731f00…` の hook が 5 つ入った状態」で、Claude Code 2.1.321 の入力を拒否して取り込みも切り直しも実際には動かない（Kusabi の SessionStart は `MALFORMED_HOOK_INPUT` の degraded。席は止まらない）。旧い版・新しい版（`28596bf0…`）の directory はどちらも消さない。

**第 3 版（2026-11-13）**: 戻した後に着く状態が変わる。**Claude の席**は、差し替え前の状態 = Kusabi の hook が 5 つとも版 `28596bf0…`（第 2 版の差し替えで入れた物。取り込みも切り直しも動く）。「旧い版 `1b731f00…` の状態」には戻さない。**Codex の席**は、差し替え前の状態 = handler 3 つが版 `dd806dbe…` で、先頭の node が存在しない（取り込みは起動できない）。戻しても取り込みは動かない状態に戻る。**見張りは、どちらの席も、戻す時は「窓を閉じる・設定から席を消す」だけで、旧い見張りに戻す物は無い**（旧い見張りは 1 度も起こしていない）。**見張りと hook は同時に戻す**（下の「見張りと hook を同時に戻す」）。版 `5fd29e06…`・`28596bf0…`・`1b731f00…`・`dd806dbe…` の directory はどれも消さない。

## 見張りと hook を同時に戻す（第 3 版。arc の判断を (c) の確かめが支える）

戻す時の順は、見張りが先、hook が後。理由（`cd-config.md` の「(c) 戻した後の読み」）: (1) 旧い見張りは、新しい終わりの値の claim を読めず（`unreadable`）、その印について何も起動しない。その周回は「観測できず」として非進捗に数えられ、連続が上限（既定 30 周。poll は 5 秒。前の版の記録は「3」と誤っていた）に届くと見張り全体が止まる（コードの読み）。(2) 旧い見張りは新しい hook の記録を確認できず（`rotation_marker_id` が null）、`unconfirmed` で席の印を置く。どちらも失敗側に倒れて壊さないが、切り直しは続かず、見張りが止まりうるので、見張りを動かしたまま hook だけ戻す形を作らない。

| 順 | 操作 | 確かめ |
|---|---|---|
| 1 | 見張りの停止の印を置き、見張りの窓を閉じる（下の「先に止める」の 1・2） | `ps` に rotation-watcher が無い |
| 2 | 見張りの設定から席を消す（Claude の席・Codex の席。見張りの設定の file は消さない） | 設定の席の数が 0 |
| 3 | Claude の席の hook を `28596bf0…` へ戻す（`rotation off` でなく、backup の復元か、`28596bf0…` を `<release>` にした同じ引数 A の差し替え） | 5 つとも `28596bf0…`、先頭が `/opt/homebrew/bin/node` |
| 4 | Codex の席の hook を backup へ戻す、または `--rotation off`（下の「Codex の席」） | 下の「Codex の席」の確かめ |
| 5 | 切り直しの記録（`<rotation root>`）は消さない（旧い見張りが読み飛ばす・新しい見張りが読める。消すのは Owner の判断） | — |

## Codex の席（第 3 版）

Codex の席の差し替え（`cd-config.md` の script B）の戻し。操作は Claude の席と同じ形で、書く file は `<Codex の作業場>/.codex/hooks.json` だけ。`~/.codex/config.toml` と、ほかの作業場の `hooks.json` には触れない。

| 戻し | 操作 | 確かめ |
|---|---|---|
| (1) 切り直しだけ止める | installer に `--rotation off`（引数 A-c を付ける。付けないと、残る取り込みの handler の node の path などが既定の値に書き換わる）。切り直しの handler（Stop 1・UserPromptSubmit 1）だけが外れる | 差分が切り直しの handler の削除だけ（`diff -u`）、残る handler は 3、すべて新しい版 `5fd29e06…` |
| (2) 全部戻す | installer が作った backup（`hooks.json.bak.wasurezu-<時刻>-<uuid>`、差し替え前の写し、0600、1 つ）を復元する。**復元の前に**、今の file の SHA-256 を、適用直後に記録した SHA-256 と比べ、違えば上書きせず止まって Owner に見せる。script は、読み戻しが合わない時、今の file が書いた直後の file と同じ時だけ自分で backup に戻す | file の SHA-256 が backup と同じ。handler が 3 つで、すべて `dd806dbe…` を指す。復元の後の `--check`（新しい版の引数）は `config_match: different`・終了コード 1 が期待。この状態は、先頭の node が存在しないので Codex の取り込みは動かない（差し替え前と同じ） |
| (3) 会話を戻す | 切り直しが起きた後、前の会話へ戻したい時は `codex resume <old_session_id>`（`old_session_id` は `watcher-ledger.jsonl` の `intent` の行） | 前の会話が開く |
| (4) 信頼の印 | 差し替えで `~/.codex/config.toml` の `[hooks.state]` の信頼の印は、席も script も書かない。戻した後、handler の中身が差し替え前に戻れば、信頼の確認が再び求められる場合がある（席は確かめていない） | Owner が画面で確かめる |
| (5) 起動の script | arc が作る新しい起動の script（O13）は、戻しても消さない（見張りの設定から外すだけ）。tmux の起動 command は、Codex の席を新しい script で起こし直した場合は新しい script を指す。元の `/tmp` の下の script は存在しないので、元の起動 command には戻せない | 戻す必要がある時は arc の判断（Owner に見せる） |

## 先に止める（どの段で失敗しても最初に行う）

| 順 | 操作 | 効き方 |
|---|---|---|
| 1 | 見張りの停止の印を置く（全体の印、または席ごとの印） | 見張りが次の周回で止まる。起動し直しは起きなくなる |
| 2 | 見張りの窓を閉じる | 見張りの process が終わる |
| 3 | 見張りの設定から席を消す | 次に見張りを起こしても、その席に触れない |
| 4 | installer に `--rotation off` を渡す（S4 の戻し）。**引数は差し替えと同じ A（`--node-path /opt/homebrew/bin/node` を含む）を付ける**。付けないと、残る取り込みの hook の node の path が、installer を動かした node の実体の path に書き換わる | 席の hook から切り直しの hook が外れる。席は切り直しの印を出さなくなる。取り込みの hook は新しい版のまま残る |

1〜3 は設定の file の変更だけで、再起動を要さない。4 は席の次の起動から効く。

## 席の会話を戻す（切り直しが起きた後に、前の会話へ戻したい時）

切り直しの記録（`watcher-ledger.jsonl`）の `intent` の行に、前の会話の `old_session_id` がある。前の会話は消えていないので、次で再開できる:
- Claude Code の席: `claude --resume <old_session_id>`
- Codex の席: `codex resume <old_session_id>`

新しい会話の中身は消えない。席の起動の script は新しい会話を作るだけで、前の会話を消さない。

## 失敗の形ごとの対応

| 形 | 見分け方 | 対応 |
|---|---|---|
| 新しい会話が起きず、席が止まる（R-E） | pane が起動の script の失敗の表示で止まっている、または pane が shell に戻っている | 先に止める 1〜3。人が席を起こし直す。起動の script が原因なら、arc が直して新しい SHA-256 を渡し、登録し直す |
| 書きかけが消えた（R-A） | 入力欄に打ちかけた文が切り直しで消えた | 受け入れた危険。失敗ではない。消えた分は人が打ち直す |
| 作業が途中で切れた（R-B）。この席では走っている AI-DLC の hook も含む（C6） | 席が応答の途中で起動し直された。respawn は pane の process 群を終わらせるので、`continue-workflow` などの AI-DLC の hook も切れる | 受け入れた危険。前の会話を再開して続ける（上の再開）。AI-DLC の段が途中なら、再開の後に `aidlc engine orchestrate next` で状態を読み直す |
| 見張りが止まった後、印を消しても再開しない（C4） | 窓に見張りの process が無い。直前の記録が、記録できない・非進捗の上限による全体の印 | 全体の印（見張り自身が書いた物）は process が終わる設計。印を消して、人が窓で見張りを起こし直す |
| 席の印を消すと再開する（C4） | 記録が、確認できず・結果不明による席の印 | loop は続いている。原因を Owner に見せた後で印を消せば、次の印から再開する |
| 見張りが想定外の席に触れた | 記録に登録外の席の行 | 先に止める 1〜3。設定を確かめる。ここで止めるのは、決定の範囲（Kusabi の席だけ）を超えた恐れがあるため、Owner に見せる |
| 取り込みの誤りの記録の増加が再開した | file の大きさが増える | S2 の戻しが行われたか確かめる。止めたはずなら原因を調べる（Owner に見せる） |
| 差し替えの後も Kusabi の SessionStart が `degraded`／`MALFORMED_HOOK_INPUT`（第 2 版） | C2 の取り直しで `hook.input_valid: false`。席は止まらない（fail-open） | 先に止める 1〜3。出力をそのまま Owner に見せて止まる。直しは追加の key の調べ（診断の記録に名前が出る場合がある）を経て arc が決める。戻しは上の S3・S4 |
| Stop 系の拒否が続き、取り込み・切り直しが動かない（第 2 版。静かな故障） | 取り込み・切り直しの証拠が `malformed_input` のまま。診断の記録に Stop の key の名前が出ない、または出ても拒否が続く | 席は止まらない（通す + 証拠）が、切り直しは始まらない。見張りを起こさない（S5 に進まない）。出力を Owner に見せて止まる |
| 診断の記録が増える（第 2 版） | `hook-input/kusabi/agent-memory/` の file の数・大きさ | 件数 32・file 64 KiB に上限がある（超えた名前は件数だけ数える）。席は止まらない。証拠でなく、契約の外。file は Owner の判断なしに消さない。旧い版に戻せば新しい書き込みは止まる |
| hook の先頭の node が動かない（第 2 版） | 読み戻しの `node --version` が失敗、または `/opt/homebrew/bin/node` が無い・実行できない | `/opt/homebrew/bin/node` の実在を直す（node の入れ替えの後の symlink の確認）。直せなければ、戻し（S3・S4 の backup の復元）。hook は失敗しても席を止めない |
| 取り込みが実際に始まり、DB に会話の行が入った（第 2 版。O1・O4） | `auto_receive.status` が `captured`、DB の会話の件数が増える | 受け入れた効果（Owner の決定と、script が #49 に投稿する記録）。止める時は戻し（S3・S4 の backup の復元。旧い版は取り込みを実際には行わない）。入った行は消さない（Owner の判断） |

## 止まる条件（Owner に見せて止まる）

- いずれかの読み戻しが期待と違う（C2 の取り直しの項目を含む）。
- 席の画面が想定と違う（別の process が前面にある、窓が無い）。
- 設定の差分に、手順に無い変更が含まれる。
- 道具が衝突・不一致の誤りを返した（同じ所で 2 回目も同じ誤りなら、出力をそのまま Owner に見せて止まる）。
