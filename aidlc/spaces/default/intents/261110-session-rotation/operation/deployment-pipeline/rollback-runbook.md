# 戻しの手順 — 会話の切り直し（261110-session-rotation）

`cd-config.md` の各段に対応する戻し。どの戻しも、戻す前に今の状態を証拠に取り、戻した後に読み戻す。DB は変えていないので、DB の戻しは無い。

## 先に止める（どの段で失敗しても最初に行う）

| 順 | 操作 | 効き方 |
|---|---|---|
| 1 | 見張りの停止の印を置く（全体の印、または席ごとの印） | 見張りが次の周回で止まる。起動し直しは起きなくなる |
| 2 | 見張りの窓を閉じる | 見張りの process が終わる |
| 3 | 見張りの設定から席を消す | 次に見張りを起こしても、その席に触れない |
| 4 | installer に `--rotation off` を渡す（S4 の戻し） | 席の hook から切り直しの hook が外れる。席は切り直しの印を出さなくなる |

1〜3 は設定の file の変更だけで、再起動を要さない。4 は席の次の起動から効く。

## 段ごとの戻し

| 段 | 戻し | 確かめ |
|---|---|---|
| S6（見張り） | 上の 1〜2 | 見張りの process が無い。記録に停止の行 |
| S5（登録） | 見張りの設定から席の項目を消す。元の設定の写しがあれば復元 | 設定の席の数が登録前に戻る |
| S4（切り直しの hook） | `--rotation off` で `--apply`（切り直しの handler だけが外れ、取り込みの hook と AI-DLC の hook は残る）。または S4 の backup（`settings.json.bak.wasurezu-<時刻>-<uuid>`、S3 の後の状態）を復元する。復元の前に、今の設定の SHA-256 を適用直後の SHA-256 と比べ、違えば上書きせず止まって Owner に見せる | 設定の差分が切り直しの hook の削除だけ（`diff -u`）。無関係な hook の数が変わらない |
| S3（取り込みの hook を入れた） | installer が作った backup（`settings.json.bak.wasurezu-<時刻>-<uuid>`、適用前の設定の写し、0600）を復元する。**復元の前に**、今の設定の SHA-256 を、適用直後に記録した SHA-256 と比べ、違えば（他者が変えたので）上書きせず止まって Owner に見せる。復元の後の `--check` は `config_match: different`・終了コード 1 が期待（取り込みの hook が無い状態 = 元）。rollout の道具の `restorePreimage` はこの席には使わない（この作業場を対象にしないため）。Owner の script は、読み戻しが合わない時に、今の file が書いた直後の file と同じ時だけ自分で backup に戻す | file の SHA-256 が backup と同じ（読み戻しに書く）。取り込みの hook が 0。AI-DLC の hook の数が適用前と同じ |
| S2（古い常駐） | Owner の決定を得て、launchd の job を有効に戻し起動する。戻すと同じ誤りで落ち続ける（誤りの記録の増加が再開する）ので、戻すのは「止めた方が悪い」と分かった時だけ | job が読み込まれる |
| S1（版） | 戻さない。中身の決まった版は消さない（古い版も新しい版も残す） | — |

## 席の会話を戻す（切り直しが起きた後に、前の会話へ戻したい時）

切り直しの記録（`watcher-ledger.jsonl`）の `intent` の行に、前の会話の `old_session_id` がある。前の会話は消えていないので、次で再開できる:
- Claude Code の席: `claude --resume <old_session_id>`
- Codex の席: `codex resume <old_session_id>`

新しい会話の中身は消えない。席の起動の script は新しい会話を作るだけで、前の会話を消さない。

## 失敗の形ごとの対応

| 形 | 見分け方 | 対応 |
|---|---|---|
| 新しい会話が起きず、席が止まる（R-E） | pane が起動の script の失敗の表示で止まっている、または pane が shell に戻っている | 先に止める 1〜3。人が席を起こし直す。起動の script が原因なら、arc が直して新しい SHA-256 を渡し、登録し直す |
| 書きかけが消えた（R-A） | 入力欄に打ちかけた文が切り直しで消えた | 受け入れた危険。失敗ではない。消えた分は人が打ち直す |
| 作業が途中で切れた（R-B）。この席では走っている AI-DLC の hook も含む（C6） | 席が応答の途中で起動し直された。respawn は pane の process 群を終わらせるので、`continue-workflow` などの AI-DLC の hook も切れる | 受け入れた危険。前の会話を再開して続ける（上の再開）。AI-DLC の段が途中なら、再開の後に `aidlc engine orchestrate next` で状態を読み直す |
| 見張りが止まった後、印を消しても再開しない（C4） | 窓に見張りの process が無い。直前の記録が、記録できない・非進捗の上限による全体の印 | 全体の印（見張り自身が書いた物）は process が終わる設計。印を消して、人が窓で見張りを起こし直す |
| 席の印を消すと再開する（C4） | 記録が、確認できず・結果不明による席の印 | loop は続いている。原因を Owner に見せた後で印を消せば、次の印から再開する |
| 見張りが想定外の席に触れた | 記録に登録外の席の行 | 先に止める 1〜3。設定を確かめる。ここで止めるのは、決定の範囲（Kusabi の席だけ）を超えた恐れがあるため、Owner に見せる |
| 取り込みの誤りの記録の増加が再開した | file の大きさが増える | S2 の戻しが行われたか確かめる。止めたはずなら原因を調べる（Owner に見せる） |

## 止まる条件（Owner に見せて止まる）

- いずれかの読み戻しが期待と違う。
- 席の画面が想定と違う（別の process が前面にある、窓が無い）。
- 設定の差分に、手順に無い変更が含まれる。
- 道具が衝突・不一致の誤りを返した（同じ所で 2 回目も同じ誤りなら、出力をそのまま Owner に見せて止まる）。
